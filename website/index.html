Hi! I'm Hina — I ship only the bits that changed ✨

Patch only what changed.

An open-source, rsync-like patcher for game clients & desktop apps — and a cross-platform package manager with Flatpak-style sandboxing.

Get started How it works
hina — bash — patch demo
⟳

I'm a delta patcher

I compare your local files with rolling checksums and download only the chunks that differ, then rebuild & verify each file in place. Content-defined chunking keeps dedup high even when files shift.

📦

…and a package manager

Install, update & remove desktop apps from a signed descriptor — with sandboxing enforced before the app starts: Landlock (Linux), Seatbelt (macOS), AppContainer (Windows) new 1.6.

Here's what's in my toolbox 🧰

Built for fast, verifiable updates

⚡ rsync-like delta patching

Rolling-checksum matching transfers only changed blocks.

🧬 Content-defined chunking

FastCDC-style boundaries dedupe across inserts & deletes.

✍️ Ed25519 manifest signing

Every manifest verified before any patching starts.

🔎 Per-chunk & per-file hashing

Integrity checks at download, rebuild & swap.

🗜️ Brotli chunk storage

Compressed, content-addressed blocks cut bandwidth.

🔁 Retry with backoff

Auto-recovery from transient 5xx & network errors.

↩️ Backup & rollback

Auto backups → instant rollback when a patch fails.

🧵 Concurrent downloads

Configurable parallelism for faster patching.

🛡️ Flatpak-style sandboxing

Filesystem & network scope on Linux/macOS/Windows.

🌐 Static hosting

Bundled host, or any CDN / Nginx / S3.

📋 Structured logging

Microsoft.Extensions.Logging + --verbose.

🔓 Open source end-to-end

Apache-2.0, no proprietary services.

Let me show you how I work 🚚

Build once, ship chunks

build pipeline
$ hina-builder build ./dist
# 1 · scan & chunk your build artifacts
✓ manifest.json — files, hashes, chunk map, signature
✓ chunks/ — Brotli blocks by content hash
# 2 · upload to Hina.Host / Nginx / S3 / CDN
client patch
$ hina update game
✓ fetch manifest · verify Ed25519 signature
⟳ rolling-checksum scan of local files
↓ download missing chunks · concurrent · retry
✓ rebuild · verify hash · swap (or rollback)
Pop me on your machine in one line 💾

Install Hina

install
$curl -fsSL https://raw.githubusercontent.com/Arutosio/Hina/master/scripts/install.sh | bash

Lands in ~/.local/bin/hina. Verifies the SHA-256 before extracting.

>iwr -useb https://raw.githubusercontent.com/Arutosio/Hina/master/scripts/install.ps1 | iex

Installs to %LOCALAPPDATA%\Hina\bin and adds it to your user PATH — no admin.

>scoop install https://github.com/Arutosio/Hina/releases/latest/download/hina.json

Auto-updates afterwards with scoop update.

Prefer a double-click installer? Grab the per-user MSI (x64 / arm64) from the latest release.

Download from Releases ↗

Then run hina --help. Verify a release with the published .sha256 sums.

I come in five neat little parts 🧩

One toolkit, five parts

hina (CLI)

install · update · run · perms · host — the user-facing command.

Hina.PackageManager

Install/update engine, descriptor schema, signatures, sandbox backends.

Hina.Builder

Turns a build dir into a manifest + content-addressed chunk store.

Hina.Host

ASP.NET Core static host: rate-limit, health, multi-app serving.

Hina.Core

The reusable library: chunking, rolling checksum, verify, retry.
