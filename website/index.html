Ship updates that move only what changed.

Hina is an open-source, rsync-like patcher for game clients and desktop applications — and a cross-platform package manager with Flatpak-style sandboxing. Rolling-checksum delta transfers, Ed25519-signed manifests, Brotli chunk storage. Standalone CLI or an embeddable library.

Get started How it works
⚡ Transfers only changed chunks 🔒 Sandboxed on Linux · macOS · Windows 🧩 No proprietary services
⟳

A delta patcher

Hina computes rolling checksums against local files and downloads only the chunks that differ, then rebuilds and verifies each file in place. Content-defined chunking keeps deduplication high even when files grow or shift.

📦

A package manager

Install, update and remove desktop apps from a signed descriptor — with Flatpak-style filesystem isolation enforced before the app starts: Landlock on Linux, Seatbelt on macOS, and AppContainer on Windows new in 1.6.0.

Built for fast, verifiable updates

Everything you need to patch a 50 GB game over a thin pipe — safely.

⚡ rsync-like delta patching

Rolling-checksum matching transfers only changed blocks, not whole files.

🧬 Content-defined chunking

FastCDC-inspired boundaries dedupe well across insertions and deletions.

✍️ Ed25519 manifest signing

Every manifest is cryptographically verified before any patching begins.

🔎 Per-chunk & per-file hashing

Integrity checks at every stage — download, rebuild and swap.

🗜️ Brotli chunk storage

Compressed, content-addressed blocks cut server bandwidth and storage.

🔁 Retry with backoff

Automatic recovery from transient 5xx and network errors.

↩️ Backup & rollback

Automatic backups enable instant rollback when a patch fails.

🧵 Concurrent downloads

Configurable parallelism for faster patching on fat pipes.

🛡️ Flatpak-style sandboxing

Filesystem & network scope enforced on Linux, macOS and Windows.

🌐 Static hosting

Ship the bundled ASP.NET Core host, or any CDN / Nginx / S3.

📋 Structured logging

Built on Microsoft.Extensions.Logging with --verbose debug output.

🔓 Open source end-to-end

How it works

Build once, ship chunks. Clients fetch only what they're missing.

Build pipeline

  1. Build artifactsyour game / app files
  2. Hina.Builderscan + chunk
  3. manifest.jsonfile list, hashes, chunk map, optional signature
  4. chunks/Brotli blocks stored by content hash
  5. Static host / CDNHina.Host, Nginx, S3…

Client patch pipeline

  1. Fetch manifestverify Ed25519 signature
  2. Rolling-checksum scancompare local files
  3. Download missing chunksconcurrent · retry + backoff
  4. Rebuild & verifyhash-check, then swap in place
  5. Success or rollbackrestore from backup on failure

Install in one line

Self-contained binary — no runtime to install. Pick your platform.

curl -fsSL https://raw.githubusercontent.com/Arutosio/Hina/master/scripts/install.sh | bash

Lands in ~/.local/bin/hina. Verifies the SHA-256 of the download before extracting.

iwr -useb https://raw.githubusercontent.com/Arutosio/Hina/master/scripts/install.ps1 | iex

Installs to %LOCALAPPDATA%\Hina\bin and prepends it to your user PATH — no admin needed.

scoop install https://github.com/Arutosio/Hina/releases/latest/download/hina.json

Auto-updates afterwards with scoop update.

Prefer a double-click installer? Grab the signed-per-user MSI (x64 or arm64) from the latest release — installs to %LOCALAPPDATA%\Hina\bin, no admin.

Download from Releases ↗

Then run hina --help. Verify a release with the published .sha256 sums.

One toolkit, five parts

Use the CLI, or embed the core library in your own app.

Hina.CLI

The hina command: install, update, run, perms, host — the user-facing entry point.

Hina.PackageManager

Install/update engine, descriptor schema, signature chain and the sandbox backends.

Hina.Builder

Turns a build directory into a manifest + content-addressed chunk store.

Hina.Host

Bundled ASP.NET Core static host with rate-limiting, health and multi-app serving.

Hina.Core

The reusable patching library: chunking, rolling checksum, verification, retry.
